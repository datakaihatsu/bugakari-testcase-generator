# 汎用テストケース生成仕様 (v2.1: 列形式CSV + 乖離チェック)

初版: 2026-05-21（32-4527 裏込砕石工から抽出）
v2: 2026-05-28（列形式CSV対応・flow_walker導入・yaml axis_behaviors導入）
v2.1: 2026-05-28（①.5 乖離チェック追加・緩和一致率 平均96%）

---

## 目的

どんな工種のJSONが来ても、**テスター操作可能な列形式テストケースCSV**を自動生成できるパイプラインの設計書。
工種を重ねるたびに「共通パターン」と「工種固有パターン」を分離・追記していく。

---

## パイプライン構成（①→①.5→②→③）

```
旧JSON + 新JSON
    ↓
① 差分抽出（extract_diff.py）
    → step1.0_差分レポート.csv
    ↓
①.5 乖離チェック（check_alignment.py）  ← 2026-05-28追加
    入力: step1.0_差分レポート.csv + 修正方針.txt
    → step1.5_乖離チェック.csv  (一致率・検出漏れの監視)
    ↓
② テスト計画生成（generate_proposals.py）
    → step2.0_テスト計画.csv
    ↓
③ テストケースCSV生成（generate_csv.py）
    → step3.0_テストケース.csv    (列形式)
```

実行コマンド:

```
python 共通/pipeline.py <old_json> <new_json> <output_dir>
```

### 処理の分担

| ステップ | 処理内容 | 自動化度 |
|---|---|---|
| ① 差分抽出 | JSON比較 → 代価表/計算表/質問/質問設定/選択肢/フローの変更を検出 | 完全自動 |
| ①.5 乖離チェック | 修正方針.txt と step1 を照合 → 一致率算出・検出漏れ監視 | 自動(キーワード+カテゴリ) |
| ② テスト計画 | flow_walker でフロー実行可能な軸を抽出 → vary/auto/fix に分類 | 自動（yaml axis_behaviors を参照） |
| ③ CSV生成 | テスト計画 + Expression評価器 + flow_walker → 列形式CSV出力 | 完全自動 |

## ③ テストケース仕様（step3.0_テストケース.csv : 列形式)

### 設計思想

「テスト軸の値の組合せをそれぞれTC1件にする」。

vary 軸 (新規追加質問・選択肢追加/削除があった質問、業務ルールで vary 昇格した質問) の **デカルト積**で TC を列挙。
fix 軸 (UI見えるがこのバージョンで変更がない質問) は **デフォルト値で固定**して全TCで同じ値を表示。
auto 軸 (AutoSelectJoken で自動確定する質問) は **"(固定)"** 注記付きで列表示、または除外。

### 出力列構成

```
テストID, テスト区分, [軸1の列ラベル], [軸2の列ラベル], ..., 期待:S1, 期待:S2, ..., 期待:S5, 選択肢の適切さ確認
```

- 軸列: SitsumonNo 昇順
- 期待:S{N} 列: 新JSON.KeisanItem に S1〜S5 が存在するもののみ
- 「選択肢の適切さ確認」: vary軸が新規追加質問・選択肢追加の場合、テンプレ文を自動生成

### 値の決定ロジック

1. **baseline scope 構築**: vary 無しで flow_walker を走らせ、全 auto-selectable 変数を確定
2. **各TC**: baseline を起点に vary軸の変数を上書き → S1〜S5 を `KeisanHyo.value()` で計算
3. **代価表行 active 判定**: TC専用 walker を走らせ、Mesho パターン `"N=代価表X枚目Y行目"` から `(sheet, row)→value` のフラグ取得
4. **空欄判定**: `(sheet=1, row=N) → 0` のとき、S{N} 列は空欄

### グループ化ルール（テスト区分=差分 1件 = TC1件)

vary 軸を Cartesian で展開した結果がそのまま TC 件数。
（v1 旧仕様の「計算式変更全件まとめて1件」等のグルーピングは廃止。テスター操作可能な「シナリオ単位 = vary軸値の組合せ」が新基準。）

## ② テスト計画仕様（step2.0_テスト計画.csv）

### 役割

新JSON の構造を解析し、テストケースに必要な「軸」を特定して分類する。
**v1 の差分起点ロジックから、JSON 全体解析ベースに刷新。**

### 出力列

| 列名 | 内容 |
|---|---|
| 軸ID | AX-001, AX-002, ... |
| 軸名 | UI表示名 (SitsumonItem.Mesho) |
| 種別 | vary / auto / fix |
| SitsumonNo | 該当する SitsumonItem.SitsumonNo |
| 列ラベル | 出力CSV列名 (auto時は末尾に "(固定)") |
| 変更理由 | varyの根拠 (新規追加 / 選択肢追加 / 業務ルール: ...) |
| 備考 | 補足情報 |

### 軸分類ロジック

1. **UI可視判定**: SitsumonKind=17(数値) or 19(選択式)、Mesho が技術ラベル (`A=10` 等) でない、SitTabRows<=4 で AutoSelect 行が1個だけのパターン除外
2. **フロー到達判定**: flow_walker(vary無し) で訪問された Sitsumon のみ候補
3. **auto判定**: walker の row_sources が 'auto' かつ SitsumonExecuteKind=2 → 除外
4. **vary判定**:
   - 差分由来: 質問追加 / 選択肢追加・削除 で検出
   - 業務ルール由来: `global_rules.yaml` の `axis_behaviors` を適用 (例: 資材計上区分)
5. **残り → fix**

## エンジンコンポーネント

### Expression評価器 (`expression.py`)

`source_ref/sirius/Being/Core/Expressions/Parser.cs` に準拠した Python版。

主要機能:
- Decimal 主体、`^` のみ float 計算 → 特定パターンは Decimal に戻す
- `0除算 → 0`、`負底のべき乗 → 0`
- 比較演算結果は 真=Decimal(1), 偽=Decimal(0)
- `IF(c, t, f)` / `&&` → `IF(L, R, 0)` / `||` → `IF(L, 1, R)` で AST 展開
- 識別子: 英字/`'`/`@`/`_`/`~`/Unicode 128+
- `@N` 参照は `ExternalReferenceError`
- 組込関数: ROUND / ROUNDDOWN / UPPER / IF

`KeisanHyo` クラス:
- 遅延評価 + キャッシュ + 循環参照検出
- `set_input(name, value)` でユーザ入力上書き
- `strict_undefined=True` で leaf 未確定変数を `UndefinedVariableError` 化
  (Expression 経由の未確定は緩和 = 0 で代用、leaf 直参照だけ厳格)

### Flow走査 (`flow_walker.py`)

`FlowItems` を Start から traverse。

- **Start 判定**: `FlowItemFlags=[0]`
- **真の終端**: `CallBox=[-1]` または empty
  - `FlowKind=4 (End)` でも `CallBox` が非空なら通り抜ける(中間終点パターン)
- **Bunki(分岐) の遷移**: 選択行 → CallBox インデックス(選択可能行の順位対応)
- **行選択優先順位**: vary > AutoSelectJoken真(auto) > SitTab.DefaultRowID(default) > 先頭(first)
- **変数伝搬**: 選択行の SitCol(VarName列) Cell 値で `KeisanHyo.set_input`
- **代価表行フラグ**: 訪問 Sit の `Mesho` で `"N=代価表X枚目Y行目"` をパースし `{(sheet,row): value}` を返す

## ⚠ Claude判定の暫定運用と将来の置き換え戦略

### 現状の位置づけ

①.5 乖離チェックの **機械評価で 70〜80% 一致** が現実的なライン。
残り 20〜30% の項目(曖昧表現・業務的に妥当な未検出など) について、
**現状は Claude(ローカル稼働)が会話で個別にリスク評価して補完** している。

```
[機械評価 70〜80%] + [Claudeリスク評価 残り20〜30%] = 実質100%
```

### 暫定運用であることの認識

Claude(本ツール開発で利用しているローカルClaude)による判定は **暫定運用**である。
本番運用を視野に入れた場合、以下の理由で何らかの仕組みへ置き換える必要がある:

- ローカル Claude の利用がいつまで継続できるか不明
- CI/CD 等の自動実行環境に組み込めない (会話前提のため)
- 判定結果の再現性が保証できない (同じ入力でも回答が揺れる可能性)
- 業務担当者が直接判定できる仕組みの方が望ましい

### 将来の置き換え候補

| 候補 | 仕組み | 長所 | 短所 |
|---|---|---|---|
| **A. 業務知識辞書(yaml)の蓄積** | 過去の Claude判定をパターン化し `claude_risk_judgement.yaml` に蓄積 → 機械評価時に自動適用 | 自動化済・再現性高 | 新パターンが出るたびに辞書更新が必要 |
| **B. 静的リスク判定ルール** | 「曖昧表現リスト」「妥当な未検出パターン」を yaml で持つ → 機械評価時に自動適用 | 中規模実装で済む | 業務ルール変更時に追従が要る |
| **C. 業務担当者の手動判定** | step1.5_乖離チェック.csv の「リスク評価」「コメント」列を業務担当者が記入 | 業務知識の正解性が保証 | 工数発生・属人化 |
| **D. 外部 LLM API 呼び出し** | pipeline.py が Anthropic API 等を呼び出してリスク評価 | 自動化・更新性高 | API コスト・外部依存 |

**当面の推奨**: A + B のハイブリッド。

- B (静的ルール) で大半の曖昧表現を吸収
- A (辞書蓄積) で工種固有の判定を再利用
- それでも残るケースだけ Claude or 業務担当者が手動判定 (C)

### 移行計画(概要)

1. **現在**: Claude(対話)で判定 → CSVのリスク評価列を手動更新 (本セッション)
2. **次フェーズ**: Claude判定を `claude_risk_judgement.yaml` に蓄積し、pipeline で自動適用
3. **本番フェーズ**: 蓄積された yaml を静的ルール化・属人性排除 → Claude依存をゼロに

## 業務知識ルール (`共通/knowledge/global_rules.yaml`)

JSON 構造から取れない業務概念のみを記述。**追加は人間に必ず確認**。

### v3 構造 (2026-05-28)

```yaml
version: 3

expected_value_policy:
  change_only_overrides: []     # 外部単価依存の手動指定(初期は空)

scenario_policy:
  grouping: {代価表: per_change, 計算表: all_together, ...}
  verification_method: {代価表: 目視確認, 計算表: 計算値確認, ...}

axis_behaviors:
  - axis_name: "資材計上区分"
    role: material_inclusion_toggle
    promote_to_vary_when:
      condition: change_affects_suryo_via_axis_switch
```

### axis_behaviors の検出ロジック

- `axis_name` の Sitsumon が UI可視軸に含まれる
- `condition: change_affects_suryo_via_axis_switch` の場合:
  diff に 計算表 変更があれば vary 昇格

## JSON構造の共通パターン（工種横断）

| キー | 内容 |
|---|---|
| `KeisanItem` | 計算式定義（Expression/Value）。VarName/Mesho にセクション見出し `<...>` も含む |
| `SitsumonItem` | 質問項目定義 (SitsumonKind, SitsumonExecuteKind, Mesho) |
| `Sitsumon019` | 条件分岐テーブル (SitCols/SitRows/SitTabRows/SitTabCells/AutoSelectJoken) |
| `Sitsumon105` | 計上コマンド (VarName, KeijoSaki) |
| `Sitsumon113` | 操作コマンド |
| `SitTab` | デフォルト値 (DefaultRowID)・コメント |
| `FlowItems` | 質問フロー (PanelNo/BoxNo/CallBox/FlowKind/FlowItemFlags) |
| `DaikaItem` | 代価表項目定義 (TankaCD, HyoKind, YosoCD) |
| `DaikaItemLine` | 代価表の明細行 (Suryo, BikoShikiLinkKeisanItemCD) |

### Mesho パターンの意味

- `"<業務的なまとまり>"` (例: `<歩掛数値の計算>`, `<内部変数>`): KeisanItem のセクション見出し
- `"N=代価表X枚目Y行目"` (例: `"0=代価表1枚目4行目"`): 代価表行のactive/inactive フラグ
- `"Var=値"` (例: `"A=10"`, `"NFG1=2"`): 内部変数設定用Sitsumon (UI不可視)
