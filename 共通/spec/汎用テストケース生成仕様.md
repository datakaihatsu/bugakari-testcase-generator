# 汎用テストケース生成仕様
# 初版: 2026-05-21（32-4527 裏込砕石工から抽出）
# 最終更新: 2026-05-27（①②③完了・全8工種でパイプライン通し動作確認済み）

---

## 目的

どんな工種のJSONが来ても、テストケースCSVを自動生成できるパイプラインの設計書。
工種を重ねるたびに「共通パターン」と「工種固有パターン」を分離・追記していく。

---

## パイプライン構成（①②③）

```
旧JSON + 新JSON
    ↓
① 差分抽出（extract_diff.py）
    → step1_差分レポート.csv    ← 本仕様で定義
    ↓
② テスト提案リスト生成（generate_proposals.py）
    → step2_提案リスト.csv
    ↓
③ テストケースCSV生成（generate_csv.py）        ← ③未実装
    → step3_テストケース.csv
```

実行コマンド:
```
python 共通/pipeline.py <old_json> <new_json> <output_dir>
```

### 処理の分担

| ステップ | 処理内容 | 自動化度 |
|---|---|---|
| ① 差分抽出 | JSON比較 → 代価表/計算表/質問/フローの変更を検出 | 完全自動 |
| ② テスト提案 | 到達不可能パス除外・テスト軸の候補提示 | 自動（ルールベース） |
| ③ CSV生成 | ②の提案からテストケースCSVを出力 | 完全自動 |

## ③ テストケース仕様（step3_テストケース.csv）

### 設計思想：「変更点ごとのTC」ではなく「確認シナリオごとのTC」

step3 は step2 の提案リストをそのまま TC1件に変換するのではなく、
**意味のある単位でグループ化**してから TC を生成する。

> ❌ 誤った生成方法（旧設計）: 計算変数が3件変更 → TC 3件
> ✅ 正しい生成方法（新設計）: 計算変数が3件変更 → TC 1件（「計算式変更（3件）」として統合）

これにより step2 の提案件数に対して TC 件数が大幅に削減される（通常 60〜85% 削減）。

### 出力列

| 列名 | 内容 |
|---|---|
| テストID | TC-001, TC-002, ... |
| テスト区分 | 差分 / 回帰 |
| 変更概要 | 何の差分に対するテストか（複数変更はまとめて記載） |
| 入力条件 | 確認に必要な入力値のシナリオ（「質問名: 選択値」または「任意」） |
| 期待確認内容 | 何を確認するか（複数変更は箇条書き） |
| 確認方法 | 目視確認 / 計算値確認 / フロー遷移確認 |

### グループ化ルール（step2提案→TC変換）

| カテゴリ | グループ化単位 | 結果TC数 |
|---|---|---|
| 代価表 | 変更1件ごと | 1件/変更 |
| 計算表 | **全件まとめて1件** | 1件（変数いくつ変わっても） |
| 質問設定 | **全件まとめて1件** | 1件 |
| 選択肢 | **テスト軸（質問名）ごと**に1件 | 変更のあった質問数 |
| 質問 | **変更種別（追加/変更/削除）ごと**に1件 | 最大3件 |
| フロー | **変更種別（追加/変更/削除）ごと**に1件 | 最大3件 |
| 回帰 | **テスト軸が同じ提案は1件**に集約 | 重複なし |

### 確認方法の推定ルール

| カテゴリ | 確認方法 |
|---|---|
| 代価表 | 目視確認（行数・備考） |
| 計算表 | 計算値確認 |
| 質問設定 | 計算値確認 |
| 選択肢 | 目視確認（選択肢表示） |
| 質問 | 目視確認（質問・選択肢表示） |
| フロー | フロー遷移確認 |
| 回帰 | 計算値確認 |

| 02 大型ブレーカ | 7 | 6 | 14% |
| 03 送気用設備運転費 | 105 | 31 | 70% |
| 04 下地処理工(復興係数) | 28 | 9 | 68% |
| 05 コンクリート吹付機 | 8 | 5 | 38% |

| 32-4527 裏込砕石工 | 119 | 36 | 70% |

### 汎用パイプラインと工種固有スクリプトの使い分け

汎用パイプライン（step3）は「変更点の網羅的な確認」を目的とした形式であり、
工種固有スクリプト（generate_testcases.py）とは設計目的が異なる。

| 観点 | step3（汎用） | generate_testcases.py（工種固有） |
|---|---|---|
| 目的 | 変更のあった全箇所を網羅的に確認 | 実際に動かすシナリオの期待値を提示 |
| 期待値 | 「変化があること」の記述のみ | S1〜S5 の具体的な数値 |
| 入力条件 | 変更のあった質問/選択肢の操作 | 全入力の組み合わせ（省庁×施工×資材等） |
| 対象 | 全工種で汎用 | 32-4527 裏込砕石工専用 |

step3 の TC は「差分確認チェックリスト」として使い、
具体的な S1〜S5 確認は工種固有スクリプトの出力と組み合わせて使うことを想定する。

### step2からの変換ルール

- `情報` 行は除外（SF固定値メモはテスト実行の前提知識であり、テストケースではない）
- `提案ID` → `テストID`（P- → TC-、連番を振り直す）
- `根拠カテゴリ` / `根拠ID` 列を削除（テスターには不要な差分内部情報）
- `差分概要` → `変更概要` 列として集約記載

## ② 提案リスト仕様（step2_提案リスト.csv）

### 出力列

| 列名 | 内容 |
|---|---|
| 提案ID | P-001, P-002, ... |
| テスト区分 | 情報 / 差分 / 回帰 |
| 根拠カテゴリ | 代価表 / 計算表 / 質問 / 質問設定 / 選択肢 / フロー / -（回帰テスト用） |
| 根拠ID | step1差分レポートのID列と対応 |
| 差分概要 | 何が変わったかの概要文 |
| テスト軸 | どの質問を操作してテストするか（UI表示名 or 「任意」） |
| 入力値 | 具体的な選択値（or「任意」or「既存の選択肢」） |
| 期待確認内容 | 何を確認するか |
| 備考 | フロー遷移先・旧値など補足 |

### テスト区分の意味

| テスト区分 | 意味 |
|---|---|
| 情報 | テストケースではない。SF固定値など「この工種の前提条件」の記録 |
| 差分 | 変更点を確認する差分テスト（変更があったシナリオ全件） |
| 回帰 | 変更のないパスが壊れていないことを確認する回帰テスト（差分テスト軸の既存値で1件） |

### カテゴリ別の提案生成ルール

| カテゴリ | 生成する提案の種類 |
|---|---|
| 代価表 追加/変更/削除 | 差分テスト1件（目視確認） |
| 計算表 追加/変更/削除 | 差分テスト1件（計算結果確認・テスト軸=任意） |
| 質問 追加 | 各選択肢ごとに差分テスト + テスト軸を回帰候補に登録 |
| 質問 変更/削除 | 差分テスト1件 |
| 質問設定 追加/変更/削除 | 差分テスト1件（計算結果確認・テスト軸=任意） |
| 選択肢 追加 | 差分テスト1件（新選択肢） + テスト軸を回帰候補に登録 |
| 選択肢 削除 | 差分テスト1件（非表示確認） |
| フロー 追加/変更 | 差分テスト1件（遷移先を自動解決） + テスト軸を回帰候補に登録 |
| フロー 削除 | 差分テスト1件 |

回帰テストは差分テストで「テスト軸」に登録された質問ごとに1件追加（既存選択肢で確認）。

### SF固定値と省庁区分の扱い

- 新JSONでSF変数が固定値（Valueで定義）の場合 → 先頭に「情報」行を追加
  - 省庁区分はUIに表示されないため列から除外することを明記

## ① 差分レポート仕様（step1_差分レポート.csv）

### 出力列

| 列名 | 内容 |
|---|---|
| カテゴリ | 代価表 / 計算表 / 質問 / 質問設定 / 選択肢 / フロー |
| 変更種別 | 変更 / 追加 / 削除 |
| ID | 各カテゴリの識別子（下記変換ルール参照） |
| 名称 | UI表示名 or 変数名 |
| 旧値 | 旧JSONの値・式・行数など |
| 新値 | 新JSONの値・式・行数など |
| 備考 | 種別（固定値/計算式）・SitsumonKind・SitsumonVersionなど |

### 並び順

- **カテゴリ順**: 代価表 → 計算表 → 質問 → 質問設定 → 選択肢 → フロー
- **変更種別順**: 変更 → 追加 → 削除（カテゴリ内）

### ID列の変換ルール

| JSON内部表記 | 差分レポート表記 |
|---|---|
| SitsumonNo:X | 質問No:X |
| KeisanItemCD:X | 計算表変数:X |
| DaikaItemCD:X | 代価表:X |
| BoxNo:X | BoxNo:X（フロー列はそのまま） |

### カテゴリ別の検出内容

**代価表（DaikaItem / DaikaItemLine）**
- DaikaItemCDの追加・削除を検出
- DaikaItemLineの行数変化（既存CDで行数が変わった場合）を検出
- `DaikaItemLine.Biko`（備考テキスト）の変更を検出。備考列に `備考変更` を記載
- 名称解決の優先順位: `Mesho` → `Meisho` → `Name` → `TankaCD:〇〇`（外部参照標準項目）
- Biko変更はUIに表示される（テスト可能）。シナリオテストパターンへの追加は②で判断

**質問設定（Sitsumon017 / Sitsumon014）**
- カテゴリ順は `質問` の直後（代価表 → 計算表 → 質問 → **質問設定** → 選択肢 → フロー）

*Sitsumon017（数値入力設定）*
- `Sitsumon017` テーブルの追加・削除・変更を検出
- 検出フィールド: `IsKikakuKeijo`（規格名計上）/ `VarName`（変数名）/ `KeisanItemCD`（接続計算変数）/ `TaniMesho`（単位）/ `DefaultValue`
- `IsKikakuKeijo: true` = 規格名計上あり（積算画面で選択した規格名が代価表に計上される）
- 備考列に `規格名計上:あり/なし` を明記

*Sitsumon014（サブルーチン呼び出し質問）*
- `Sitsumon014.SendItemList` の変更・追加・削除を検出
- `CurVarName`（親工種側の変数名）/ `SendVarName`（子代価側の変数名）の対応変化を検出
- 表示形式: 旧値 `親:FG1→子:FG1`、新値 `親:FG~01→子:FG1`
- 子代価が受け取る値が変わるためテスト可能。シナリオテストパターンへの追加は②で判断

**選択肢（Sitsumon019.SitTabRows）**
- 既存質問への `SitTabRows` 追加・削除のみ検出（新たに選べる選択肢の増減）
- 新規追加・削除された質問の選択肢はスキップ（質問カテゴリで既に記載）
- セル値（`SitTabCells` の計設定値）はUIに表示されないため検出対象外
  - 例: 「K=425 機械数量修正」「FG1=81 を設定」などのセル値変更はシナリオテスト不可 → 除外

**計算表（KeisanItem）**
- KeisanItemCDの追加・削除を検出
- Value（固定値）またはExpression（計算式）の変更を検出
- 備考に「固定値」「計算式」「固定値→計算式」「計算式→固定値」を記載

**質問（SitsumonItem）**
- SitsumonNoの追加・削除を検出
- Mesho（表示名）の変更を検出
- **削除行**: 旧値・新値ともに `-`。SitsumonVersionは備考列に記載
- **追加行**: 新値にSitsumonVersion（追加日時）を記載

**フロー（FlowItems）**
- BoxNoの追加・削除を検出
- SitsumonNoまたはCallBoxの変更を検出
- CallBoxの遷移先はBoxNo→SitsumonNo→Meshoの順に解決してUI表示名で記載
- 旧値・新値の`SitsumonNo`表記は`質問No`に変換

## SF・SFK値の解釈ルール

### SF → 省庁区分テーブル参照ロジック

- `KeisanItem` に `VarName: SF` のレコードがあり、`Value`（固定値）または `Expression`（計算式）で定義される
- SF が固定値 → 省庁区分は自動選択・UIに表示されない → **テストケースの列から除外**
- `AutoSelectJoken` の `MaxKigou=3` は「≦（以下）」を意味する

**確認済み実測値**:

| 工種 | SF値 | 種別 | 省庁 |
|---|---|---|---|
| 32-4527 裏込砕石工 | 2.1 | 固定値（KeisanItemCD:33） | 治山林道 |
| 32-1951 大型ブレーカ | 1.0 | 固定値（KeisanItemCD:103） | 国交省土木 |
| 32-571 送気用設備運転費 | 1.0 | 固定値（KeisanItemCD:22） | 国交省土木 |

### SFK値の分岐ロジック

- `SitTab` の省庁RowIDに対して SFK1a/SFK2/SFK3/SFK4 が定義される
- SFK3 = 1 → BH施工固定 / SFK3 = 2 → クレーン施工選択可

## テスト軸の選定原則

> **「S1〜S5の値に影響するか」ではなく「実行に必要な入力か」で判断する**

### テスト軸以外の入力列の記載ルール（02・03で確立）

- **テスト軸**（検証したい入力）: 具体的な値を記載
- **テスト軸以外の入力**: 「任意」と記載
- **省庁区分**: SF固定値の場合はUIに表示されないため、**列ごと除外**する

### FlowItems BoxNo → UI表示名の解決ルール（02で確立）

`FlowItems` の BoxNo / CallBox は内部識別子であり積算画面には表示されない。
CSVの期待値には必ずUI表示名（SitsumonItem の Mesho）に変換して記載する。

解決手順:
1. `FlowItems[BoxNo].SitsumonNo` を取得
2. `SitsumonItem[SitsumonNo].Mesho` を取得（UI表示名）
3. CallBox についても同様の手順で解決

共通エンジンの `resolve_boxno_name(box_no)` / `resolve_callbox_names(box_no)` が自動解決する。

## 期待値の計算可否

| 項目 | 自動計算可否 | 理由 |
|---|---|---|
| 労務・機械数量（S1〜S5） | ○ | 歩掛値×LD で確定 |
| 砕石数量（S4） | ○ | AT × 砕石係数 で確定 |
| バックホウ運転費の金額 | ✗ | 外部単価依存 |
| 最終代価表の金額 | ✗ | 外部単価依存 |

## ユーザー選択項目の判定ルール

### 代価表当り単位が自動選択される条件（32-4527で発見）

SFK1a が省庁テーブルで固定値に設定されている場合、
ユーザーに代価表当り単位の選択UIが表示されない（AT が自動決定される）。

- SFK1a=1 → 10m3単位（AT=10）
- SFK1a=2 → 100m3単位（AT=100）
- SFK1a=0 → 日当り施工量単位（AT=D）

## 選択肢の適切さ確認（JSONから語れない観点）

JSONは実装結果であり、表示テキストの正しさをJSONから検証することはできない。
変更があった選択肢については「問いかけ」スタイルで確認項目を記載する。

**フォーマット**:
```
[変更種別]（例: 2026年新規追加）
・「[表示テキスト]」と表示されているが、外部設計と正しいか
```
