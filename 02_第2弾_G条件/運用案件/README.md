# 第2弾 G条件 運用案件（段階別フォルダ）

第1弾と同型の①〜④＋段階別フォルダ。G条件＝施工単価入力基準表(Gaia生成)の様式。

## 段階と対応
| 段階 | 内容 | フォルダ | 例(土のう積工) |
|---|---|---|---|
| ① 叩き台G条件 | 改定前(商品)JSON → G条件を逆生成 | 20_叩き台G条件/ | 2024版JSON→G条件(4条件) |
| ② 人作成G条件 | 改定後に向け人が加工したG条件(手作業) | 30_人作成G条件/ | 2026版JSONから生成=加工の土台(6条件) |
| ③ 乖離チェック | ①叩き台 vs ②人作成 の差 と 実装(JSON)差分 を照合(未実装) | 50_乖離チェック/ | ─ |
| ④ 検証用JSON | 改定後JSON(積算実体) | 40_改定後/ | 2026版JSON |
| (入力) 改定前JSON | ①の入力 | 10_改定前/ | 2024版JSON |

## G条件生成
python3 02_第2弾_G条件/gen_gjoken.py <JSON> <出力ディレクトリ>
  出力: Gaia入力基準表_<工種名>(<単位>).csv
  - G1..Gn: フロー(積算)出現順の再選択可能な選択式条件。選択肢は説明ラベル。
  - (注): オプション別ゲート検出（Gxの或る選択肢で後続Gy非到達＝不要）。
  - 単価/数量は対象外(基準書由来の知識)。

## 次: ③乖離チェック / ④検証 ロジック生成
- ③: 20_叩き台G条件 と 30_人作成G条件 の差(G追加/選択肢変更/注変更) を、40_改定後JSONの実装差分と照合。
- ④: 40_改定後JSONで積算シミュレート的な裏取り。
