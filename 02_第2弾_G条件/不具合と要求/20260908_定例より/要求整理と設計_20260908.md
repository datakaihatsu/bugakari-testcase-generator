## 1件目 — (注)に選択肢をそのままコピペしたい

> **⚠ この節の「要件」「設計」は 2026-09-09 の合意で差し替わりました。**
> 確定版は末尾の **「確定設計 A：(注)の書式を短い形へ」** を参照。
> 以下の「現象」「原因」は調査記録としてそのまま残す。

### 要求
G条件セルの選択肢文字列（`①【A=1】 一般照明器具` など）を、そのまま(注)の「」内に貼り付けたい。
今は「選択肢が条件の選択肢に存在しません」で注が丸ごと無視される。

### 現象（実測）

| 注の書き方 | 現状 |
|---|---|
| `②「 材料単価を直接入力」` | ○ 通る（現状これだけ） |
| `②「【B条件】 材料単価を直接入力」` | × ERROR |
| `①「①【H=1】 補正無し」` | × ERROR |
| `「② 材料単価を直接入力」` | × ERROR |
| `「②材料単価を直接入力」` | × ERROR |

### 原因
`gen_tc_from_gjoken.py:255`

```python
labels = [x.strip() for x in _quoted_spans(sel_part)]
```

表の選択肢セル側は `_strip_marker()`（丸数字マーカー除去 → 先頭 `【…】` コード除去）で正規化しているのに、
注の「」内は `strip()` だけ。**同じ文字列に対して左右で違う正規化をしている**のが原因。

### 要件
- **R1-1** 注の「」内の選択肢名は、表の選択肢セルと同一の正規化キーで突合する
- **R1-2** マーカーが「」の外／中／両方／無し、どれでも受理する
- **R1-3** 正規化しても一致しないものは従来どおり ERROR（誤記の検知力は落とさない）
- **R1-4** 画面・メッセージの表示は入力どおりの文字（正規化前）を出す

### 設計
`_strip_circled` / `_strip_marker` を、突合キー生成の単一関数 `_opt_key(s)` に統合する。

```
_opt_key(s):
  1. 前後空白（半角/全角）除去
  2. 先頭の ①..⑳ / (n) マーカーを **ループで** 除去   ← ①【H=1】 のような二重付与に対応
  3. 先頭の 【…】 + 続く空白 を除去
  4. 再度 strip
  ※ 文字列内部の空白は触らない（v1.2.2「条件名完全一致」方針と整合）
```

適用箇所（`read_gjoken` 内、他は不変）:
- 選択肢セル側 `cols[i]['opts']`（現 `_strip_marker`）
- 注側 `labels`（現 `strip()` のみ）
- 「～」範囲展開の `opts.index()` も同キーで動く

表示用 `opts_raw` は現行どおり丸数字だけ落として保持（R1-4）。

**影響範囲**: `gen_tc_from_gjoken.py` のみ。① と TC 生成本体は不変。

### 設計レビュー
- ✔ **上位互換**。今 OK のものは全部 OK（正規化を足すだけ）。回帰は出力不変の見込み
- ⚠ 選択肢名そのものが `【` で始まる／丸数字で始まる場合も剥がしてしまう
  → ただし**表セル側でも同じ処理をする**ので左右で同じキーになり、突合は壊れない。表示は raw を保持するため実害なし
- ⚠ `②「 材料単価を直接入力」` が今通っているのは `strip()` の副作用。統合後も通る（ステップ1）
- 📝 `webapp/test_note_parse.py` に上表5パターンをそのまま追加してロックする

## 2件目 ＋ 3件目 — (注)と列が「TC行列からの帰納」になっている

### 要求
- 2件目: `G2「照明器具1台当たりの単価計上方法」で②材料単価を直接入力 → G3「単価」不要` と
  `G9 → G10` の注が出ていない。代わりに注1（G4起点）・注5（G9→G11）に吸収されているようだ
- 3件目: 注の制約が見づらい。かつ商品から出す条件が足りていない

### 原因（21 管(函)渠型側溝で実測）

`gen_gjoken._derive_glist()` は **step3 のテストケース行列の `'-'` パターン**を排他制約の証拠として使っている。
しかし TC 行列は「テストとして必要十分な集合」であって「制約を証明する集合」ではない。

実測値:

```
TC行数 = 9行 ／ vary軸10本のうち 7本が1選択肢しか展開されない
  G4 基礎砕石の有無 : {'有り': 8, '-': 1}          ← 「無し」が1行も無い
  G5 賃料長期割引    : {'長期割引あり': 7, '-': 2}  ← 「なし」が1行も無い
  G8 内径又は内空幅  : {'-': 8, '200mm以上300mm以下': 1}
[列除外] 到達せず: 労務費の適用, 日当り作業量補正(直接入力), 側溝単価計上方法, 側溝材料単価, 管(函)渠型側溝材料区分
```

この結果、生成された注12件には**因果でない注**が混ざる:

- 「G5(0.28m3の賃料長期割引)で①長期割引ありを選択した場合は、G9(0.5m3の賃料長期割引)を入力する必要はない」
  → 賃料割引の選択がバックホウ規格を決めるはずがない。実際に決めているのは G3 側溝規格
- 「G4 基礎砕石の有無で①有りを選択した場合は、G8・G10 を入力する必要はない」
  → 「無し」が0行なので比較すらしていない

逆に**真の因果は出ない**（2件目）。真因の代わりに、たまたま同じ行で `'-'` になった上流列に吸い上げられる。
さらに**列そのものが落ちる**（3件目「商品から出す条件が足りていない」）: 21では
`側溝単価計上方法` `側溝材料単価` が「到達せず」で列にすらなっていない。

> これは v1.2.1 で潰した「縮退サンプルから(注)を誤帰納」と**同じ類型**。
> あのときは縮退ガードを廃止して直積に戻したが、**直積 combo → TC行 に落とす段階で軸が1行に間引かれる**ため、穴が残っていた。

### 要件
- **R2-1** (注) は「フロー上の到達可能性」から導く。TC行列に依存しない
- **R2-2** `Gx=v → Gy 不要` と書けるのは
  (a) Gx=v を満たす**すべての**組合せで Gy に到達しない、かつ
  (b) **Gx だけを変えると** Gy に到達する組合せが存在する（＝ Gx が真の原因）
- **R2-3** G条件の列は「いずれかの組合せで到達する質問」をすべて出す（TCで到達しなくても出す）
- **R2-4** 対象列が連続するときは「G10条件～G15条件」形式でまとめる（読みやすさ）
- **R2-5** 組合せ上限（現行3,000）超は従来どおり「生成できません」

### 設計
新モジュール `02_第2弾_G条件/gjoken_reach.py` を追加する。**TC生成パイプライン(step2/step3)は触らない。**

1. **到達マップ構築**
   UI可視な選択質問（Kind19 かつ `TestPlanGenerator._is_ui_visible_axis`）の全選択行の直積を作り、
   combo ごとに `FlowWalker(bj, vary_selections=combo).walk()['visited_sitsumons']` を1回回すだけ（期待値計算なし）。
   上限は step3 と同じ `MAX_FULL_COMBOS`。→ `reach[combo] = set(visited)`
2. **列の決定 (R2-3)** … いずれかの combo で visited な質問を、フロー出現順に並べて G列にする
3. **注の導出 (R2-2)**
   - 候補: `all(Gy ∉ reach[c] for c if c[X]==v)` かつ `any(Gy ∈ reach[c] for c)`
   - 真因フィルタ: `∃c (c[X]=v, Gy∉reach[c])` かつ `∃v'≠v: Gy ∈ reach[c[X:=v']]`
     → 「G5長期割引 → G9」型の偽注はここで落ちる
4. **注の整形 (R2-4)** … 対象列が連番なら `G10条件「A」～G15条件「F」`、飛び番は現行どおり `・` 連結
5. `gen_gjoken` は列・選択肢・注を `gjoken_reach` から受け取る。
   TC行列は **規格名計上○の判定** と **TC表示ラベル対応（disp2label）** にだけ使う

#### 代替案と却下理由

| 案 | 内容 | 判定 |

| A | 直積 combo をそのまま TC 行にする（間引きをやめる） | 却下。TCが数百件になりテスト設計として使えない |

対象部の解析を `_parse_targets(tgt_part, cols, issues, where)` に切り出す。

```
1. G(\d+)(?:条件)?(?:「(名)」)? を全て拾い、参照リストを作る
2. 参照と参照の間に ～ / ~ / - があれば「範囲」とみなし、列indexで展開

```

## 4件目① — 選択肢が数値（0.1）で出る

### 現象（65-109-64-12 現地滞在のための旅費 = 64-1538 で完全再現）

「背景グレーのセル」の正体は `SitCols[3] = {"ColID":3, "IsFixed":true}`（固定＝見出し扱いの列）で、

### 要件
- **R4-1** ③の選択肢表示は①のG条件表と同じ文字列になること（表示ルールを①③で一本化）
- **R4-2** 「規格コード併記」(J4 / 02 Sit82) の既存挙動を壊さないこと

  ヒットしないときは案Aのスコアにフォールバック。
  → 既存の「係数」列除外と同じ「見出しテキストで判断する」作法に乗るので誤爆が少ない

どちらの案でも、選定関数を共通化して**①と③が同じ関数を使う**ことが R4-1 の本体。

### 設計レビュー

## 4件目② — 「(値なし)」と 数量直入の入力範囲

## A-3. 設計

### (1) 突合キーの統一 `_opt_key()`

```
  2. 先頭の ①..⑳ / (n) マーカーを除去
  3. 先頭の 【…】 + 続く空白 を除去

```
