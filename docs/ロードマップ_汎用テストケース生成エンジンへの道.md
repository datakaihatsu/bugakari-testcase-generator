## ビジョン

> **旧JSON + 新JSON を投入するだけで、列形式テストケースCSVが自動生成される**

プロジェクトごとに改修される10〜30工種を対象に、差分抽出 → 乖離チェック → テスト計画 → 列形式CSV生成 の4ステップを自動化する。

---

## アーキテクチャ（①→①.5→②→③）

```
旧JSON + 新JSON
    ↓
① 差分抽出（決定論的・完全自動）
    → step1_差分レポート.csv

    ↓ 修正方針.txt と照合

①.5 乖離チェック（キーワード+カテゴリ照合）
    → step1.5_乖離チェック.csv  (緩和一致率 平均96%)

    ↓

② テスト計画生成（JSON解析+yaml業務ルール）
    → step2_テスト計画.csv  (vary/auto/fix軸の分類)

    ↓

③ 列形式テストケースCSV生成（Expression評価器+flow_walker）
    → step3_テストケース.csv  (列形式・期待値計算済)
```

実行コマンド:

```
python 共通/pipeline.py <old_json> <new_json> <output_dir>
```

修正方針.txt が new_json と同じディレクトリにあれば自動的に ①.5 を実行。

## ①.5 修正方針との乖離チェック (2026-05-28追加)

`共通/step1_5_check/check_alignment.py`

入力: `step1_差分レポート.csv` + `修正方針.txt`
出力: `step1.5_乖離チェック.csv` (一致率・検出漏れの監視)

### ロジック

1. 修正方針.txt をパース(【】カテゴリ・親子インデント集約)
2. 各項目からキーワード抽出(英数字識別子・質問No・数値・日本語キーワード・動詞)
3. step1 各行とカテゴリ・キーワードで照合
4. score>=2 = matched / score=1 = partial / カテゴリのみ一致 = category_partial / それ以外 = unmatched

| 工種 | 緩和一致率 |
|---|---|
| 01〜03, 05, 06, 07, 32-4527 | 100% |
| 04 下地処理工 | 67% |
| 02 大型ブレーカ | 100% |

### 機械検出不可な残部

- 「資料通りに変更」「適切な位置へ配置」のような曖昧表現
- 業務概念の言語ギャップ (「労務」 vs `S1A`)
- これらは Claude が業務文脈で補足する運用に回す

## エンジン構成要素

### Expression評価器 `expression.py`

`source_ref/sirius/Being/Core/Expressions/Parser.cs` 準拠の Python実装。

- Decimal主体・`^`のみ float
- 0除算 → 0、負底のべき乗 → 0、比較は 1/0
- `IF` / `&&` / `||` のショート評価
- `KeisanHyo.strict_undefined=True` で leaf未確定のみ厳格化

### flow_walker `flow_walker.py`

`FlowItems` を Start から traverse。

- Start: `FlowItemFlags=[0]`、真の終端: `CallBox=[-1]`
- Bunki遷移: 選択行 → CallBox[行index]
- 行選択優先: vary > AutoSelect真 > DefaultRowID > 先頭
- 代価表行フラグ: Mesho パターン `"N=代価表X枚目Y行目"` から抽出

### yaml業務ルール `global_rules.yaml`

v3:
- `expected_value_policy` / `scenario_policy` / `axis_behaviors`
- **追加は人間に必ず確認** (システマチック生成を曇らせないため)
