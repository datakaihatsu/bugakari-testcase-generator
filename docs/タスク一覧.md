## 運用ルール：工種フォルダのテストケース生成（2026-06-08 追加）

フォルダ単位の生成は `共通/run_koshu.py` を使う。次の3ルールを強制する。
使い方: `python3 共通/run_koshu.py`（全工種）/ `python3 共通/run_koshu.py 16 18`（先頭一致で指定）。

### 1. 修正方針.txt が無ければ生成しない
- `工種別/<工種>/input/修正方針.txt` が存在しない／空 の工種はスキップ（生成中止）。
- 修正方針は step1.5 乖離チェックの入力でもあり、変更意図の記録として必須。

### 2. 参考工種は input/参考/ サブフォルダに置く
- 修正方針に「※参考工種」として参照する JSON は `工種別/<工種>/input/参考/` に格納する。
- 旧/新の比較対象は **input 直下の *.json のみ**（`参考/` は再帰せず除外）。
  → ファイル名の文字ブレに依存せず、置き場所で確実に旧/新比較から外せる。
- 保険: input 直下に名前へ「参考」を含む json があれば誤配置として除外＋警告する。

### 3. モード・旧新の自動判定
- 参考を除いた直下 json が 1件 → 全パターン型 / 2件以上 → 差分型。
- 同年度2回改定（例 `…20260401(20260417).json` / `…(20260529).json`）に対応するため、
  旧/新はファイル名中の **最後の8桁日付（括弧内の改定日を含む）** の昇順で判定（古い=旧 / 新しい=新）。
